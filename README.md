# Nebula OS

Особистий NixOS flake-конфіг: один хост `earth` (AMD/RX590 десктоп) + Home Manager профіль
`ryudzyn`, зібрані разом в один flake. Детальніше про архітектуру -- в `CLAUDE.md`.

## Публічний чи приватний?

Цей репозиторій навмисно публічний. Причина -- технічна, а не "нема чого приховувати":

- **Публічний репо -- `nixos-rebuild --flake github:ryudzyn/nebula-config#earth` (або будь-який
  `nix flake` команди, що тягнуть цей репо як `github:...` посилання) працює одразу, без жодної
  автентифікації.**
- **Приватний репо -- той самий флейк-виклик впаде** з помилкою на кшталт "unauthorized"/"repository
  not found", бо Nix ходить в GitHub анонімно за замовчуванням. Щоб це запрацювало з приватним
  репо, треба або:
  - додати `access-tokens = github.com=<personal access token>` в `~/.config/nix/nix.conf` на
    **кожній** машині, де застосовуєш конфіг (токен ще й треба десь безпечно зберігати й оновлювати,
    коли він протухне), або
  - клонувати репо по SSH і застосовувати з локального шляху (`nixos-rebuild --flake
    ~/nebula-config#earth`), а не через `github:` посилання -- це працює, але вимагає, щоб клон
    (і робочий SSH-ключ) вже був на машині ще до першого `switch`.

  Саме ця плутанина (який саме шлях/токен зараз потрібен -- git-рівня SSH-ключ для push/pull, чи
  окремий Nix-рівня access-token для флейк-фетчу) і була джерелом проблем при попередній спробі
  перенести конфіг як приватний репо.

- **Перед тим як зробити репо публічним, я перевірив** (`git ls-files` + grep по всьому дереву на
  `password`, `hashedPassword`, `-----BEGIN ... PRIVATE KEY-----`, токени тощо) -- в репозиторії
  немає жодного захешованого пароля, Wi-Fi PSK, API-токена чи приватного ключа. Пароль користувача
  задається поза Nix-конфігом (не в `core/users.nix`). Якщо колись додаси щось справді секретне
  (VPN-ключ, API-токен для якогось сервісу) -- **не клади це в `.nix`-файл напряму**, а онови цей
  README і додай `agenix`/`sops-nix` для шифрованих секретів у git; доти репозиторій лишається
  безпечним публічним.

## Як застосувати на новій машині

```sh
git clone git@github.com:ryudzyn/nebula-config.git ~/nebula-config
cd ~/nebula-config
nixos-rebuild dry-build --flake .#earth   # спершу переконатись, що взагалі збирається
sudo nixos-rebuild switch --flake .#earth
```

`hosts/earth/hardware.nix` -- машинно згенерований файл (`nixos-generate-config`), прив'язаний
саме до заліза `earth`. На дійсно іншій машині його треба перегенерувати, а не тягнути as-is.
